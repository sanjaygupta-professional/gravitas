What you're looking at

Every step, each body is pulled by all 1,024 bodies (split across cores as a binary tree). What you see: the light bodies rush in toward the heavy centre around step 10, get flung outward, and the heavy body itself is dragged away from its start. The view zooms out to follow them.

Finding: the "cloud" is really 10 light bodies

In sim.bend, a body's random seed is derived from the path taken down the tree: left = next(s), right = next(next(s)). Going left-then-right gives the same seed as right-then-left, so every path with the same number of right turns lands on the same seed, and body_at uses only the seed (the index is only used to spot body 0). Result: 10 distinct light bodies, stacked in copies of 10, 45, 120, 210, 252, 210, 120, 45, 10 and 1. Identical bodies feel identical forces, so they stay stacked for the whole run. The comment "each body is determined by its index alone" is not what the code does. The proofs are unaffected, since they concern counts and mass, but the physics is far less rich than 1,024 bodies suggests.

This is a JavaScript re-implementation of main.bend / sim.bend (same seed, same constants, F32 rounding, same pairwise sum order), because the real ./sim only prints summaries. It is not the Bend binary itself; the table above compares the two.
